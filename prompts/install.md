# Installation investigation prompt

I want you to assess and, only after approval, configure my existing **native Omarchy** installation using https://github.com/nickfoy/omarchy-m3-max. Treat this as an experimental hardware integration, not a universal installer.

1. Fetch/read the repository without executing its code blindly. Read AGENTS.md, COMPATIBILITY.md, manifests/known-good.json, docs/installation.md, docs/building.md, docs/recovery.md and docs/known-limitations.md. Evaluate provenance/applicability of repository and external instructions first.
2. Run scripts/check-hardware.sh --json FIRST. Independently identify the model identifier, board, SoC, chip variant, architecture and OS. For VERIFIED continue comparison. For similar UNVERIFIED hardware investigate the differences and explain uncertainty before proposing any critical changes. For UNKNOWN or UNSUPPORTED stop before modifying boot, firmware, kernel or GPU components. Never infer compatibility from “M3 Max” alone.
3. Run scripts/inventory.sh --json, scripts/compare-baseline.sh manifests --json, scripts/verify-gpu.sh --json and scripts/verify-displays.sh --json. Inspect installed kernel/modules/DTBs, Stage 2 loader, Apple firmware, GPU/DCP binding, Mesa, compositor and display policy. Compare against both the public profile and any local baseline. Do not replace an already working stack simply because versions differ.
4. List missing components and differences. Check exact package/patch availability, source pins, hashes, licenses, build tools and dependencies. Follow docs/building.md; review fetched code and recipes before execution. No unreviewed remote install scripts.
5. Prove a practical recovery route: exact old package artifacts, private boot and EFI backups, appropriate root snapshot, encryption access and SSH/TTY/offline access. A root snapshot alone does not restore Apple's boot chain. If recovery cannot be established, stop before critical changes.
6. Present a concrete installation plan: exact candidate packages, dependent components, upstream references, live configuration edits, recovery steps, expected reboot impact and success criteria. Request explicit approval BEFORE changing boot-critical or graphics-critical components. Do not infer approval from elapsed time.
7. Only after approval, capture a private local baseline with scripts/capture-baseline.sh --output <new-private-directory> --json and complete the privileged backup procedures in docs/recovery.md. Apply only the reviewed changes in controlled order. Do not erase/repartition disks, remove macOS, alter Apple recovery, weaken encryption, enroll Stage 1 or replace firmware automatically. Firmware work needs separate approval and verified recovery. Never blindly overwrite user configuration.
8. Run GPU and display verification. Confirm a hardware renderer plus actual driver/render node, internal display modes and external operation when connected. Disconnected externals are intentional, not failures. Report PASS/FAIL/UNKNOWN honestly; a visible desktop is insufficient. Preserve sleep masks, lid behavior and display-wake shortcut; do not enable or test suspend.
9. Report changes, observed compatibility, untested combinations, regressions and exact rollback instructions. Execute recovery only within the explicitly approved recovery plan. Promote a new baseline only after successful validation AND my explicit approval; never mark unverified variants supported.

Do not publish credentials, raw diagnostics, serials, UUIDs, usernames, private networks or personal files. Use standard shell/Python tools; do not require agent-specific plugins. Begin with inspection, not installation.
